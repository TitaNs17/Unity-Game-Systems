How I work

Code that can grow with the project

Keep Unity-facing code focused

MonoBehaviours handle scene references, input and engine lifecycle. Logic that does not need Unity stays in plain C# classes where possible.

Reduce unnecessary coupling

Interfaces, events and small services make it easier to replace or extend individual systems without rewriting the rest of the game.

Build from gameplay needs

Most systems in this repository came from actual prototypes, then were cleaned up into reusable pieces after the gameplay worked.
